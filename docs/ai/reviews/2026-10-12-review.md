# Deep review (full findings)
Lead re-ran probe_rotate.py, probe_upscale.py, probe_label.py on the clone: all reproduce (r90/r270 lose BL001/BR001; 90x50 card -> 100x55.6 / 200x111.1, Scale 50% no effect; label_text ignored, contract stops at marks/preprocessors). geometry.py fitted_rect `scale=min(...)` uncapped confirmed.

## Verdict
Clean code, gates green, but the engine produces silently wrong press output in common cases and the 258 tests miss all of them. #1: any /Rotate 90/270 source page (incl. pages rotated by Laydown's own Rotate preprocessor) loses part of its artwork. Release pipeline would most likely run today.

## Findings
- F1 BLOCKER: /Rotate 90/270 pages cropped — geometry.py:115 intersects unrotated page.trimbox with rotated page.rect; PyMuPDF 1.28 show_pdf_page mishandles rotated sources even without clip (probe_rotate3). Same defect preprocessors.py:83 (_scale); preflight box checks wrong on rotated pages (preflight.py:76-92). test_engine_robustness.py:163 checks centre token only. Fix proven (probe_rotate4): page.remove_rotation() on the in-memory work doc; capture boxes as box*page.rotation_matrix first and re-set (remove_rotation resets Trim/Bleed).
- F2 HIGH: N-Up/booklet always scale to FILL the cell incl. enlarging; Scale preprocessor inert; preflight says the opposite. 90x50 cards on A4 2x4 -> 100.0x55.6 mm; 1x1 -> 200x111; +Scale 50% identical. geometry.py:133 scale=min(...) no 1.0 cap; preflight.py:140 reports shrink only; :149 detail text false.
- F3 HIGH: bleed overprints neighbour live area; booklet spine; creep crosses fold. probe_bleed (2-up 3 mm bleed 0 gutter: 1 mm inside page 1 trim is page 2 colour; fine when gutter>=bleed); probe_booklet_bleed (A5 on A4, 0 margin, 3 mm bleed: 1.5 mm inside left spine is right page colour); probe_misc E (8 mm inner creep: trims overlap across fold 217>203 mm). Preflight silent. impose.py:165 target rects spill; geometry.py:376 creep not clipped at fold.
- F4 HIGH: Text Label custom text offered in UI, ignored by engine; capability contract blind — marks_tab.py:224-227,253-254 edit label_text; marks.py _draw_text_label never reads it; capabilities._walk(Project()) (capabilities.py:78-93) stops at empty marks/preprocessors lists.
- F5 MED: all marks DeviceRGB (only rg/RG, no /Separation) — colour bar not process solids; crop/registration not on all plates. marks.py:117,145-151, _COLOR_BAR.
- F6 MED: annotations + form-field values silently dropped (probe_misc A); show_pdf_page copies contents only; Document.bake() available in 1.28.
- F7 MED-HIGH: preview does not scale — re-imposes whole job + keeps every sheet pixmap up to 300 DPI (preview_panel.py:128-148,333); 600-page 2-up ~1.6 GB @96 DPI, ~14 GB @288 DPI (probe_perf); PyMuPDF holds GIL (probe_gil: 8.3 s main-thread stall) so QThread doesn't help; _do_render cancel()+wait() on GUI thread (:339); impose not cancellable; QPixmap built off GUI thread (:143). ROADMAP Phase 4 "Preview scale" (ROADMAP.md:131) never done.
- F8 MED: preflight checks a different job — raw page 1 only, ignores page range + preprocessors (preflight.py:76,115,132); booklet range 1-8 of 10 says "10 pages padded to 12"; encrypted PDF -> preflight raises, UI swallows (main_window.py:398-401), preview shows cryptic error; missing custom-mark PDF skipped though marks.py says preflight reports it.
- F9 MED: release pipeline — runs today (Node 20 removed 2026-09-23, forced to Node 24 = warnings only; macos-15-intel valid until fall 2027; latest PyQt6 6.11.0, PyMuPDF 1.28.2 vs shipped 1.28.0, PyInstaller 6.22.3 vs 6.21.0). Gaps: tag build with missing secret still mints throwaway cert (release.yml:70-72) -> 0x800B010A repeat; build.ps1:93/102 exits 0 without MSIX if SDK missing, upload-artifact only errors on zero matches.
- F10 LOW-MED security: PyMuPDF>=1.23.0 floor (pyproject.toml:18) allows MuPDF with CVE-2026-3308 (heap OOB write, 1.27.0) and CVE-2026-25556 (double-free 1.23-1.27); shipped binaries 1.28.0; source installs only. Presets can reference UNC custom-mark paths (NTLM leak, low). Export non-atomic, can overwrite the open source file (probe_misc C).
